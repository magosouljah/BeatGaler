## 4. Findings

### P1-01 — DNS-rebinding SSRF in remote artwork fetch — FIXED IN PR #89

**Vector**  
An attacker-controlled image hostname can resolve to a public IP during `assertPublicImageUrl()`, then change DNS before `http(s).get()` resolves the hostname again. This is a classic validation/use TOCTOU and can target loopback, link-local metadata, RFC1918 or other internal services.

**Impact**  
Server-side requests to infrastructure that the URL validator intended to block; potential metadata/service probing and credential exposure depending on runtime network reachability.

**Evidence / affected path**  
`cloud-server/server-core.js`: `assertPublicImageUrl()` performs `dns.promises.lookup(..., {all:true})`; `fetchRemoteImageDataUrl()` subsequently invokes `http(s).get(url, ...)`, causing a separate connection-time resolution.

**Reproducibility**  
Deterministic safe unit test: validation returns a public address; DNS is changed to `127.0.0.1` before the outbound connection. No external host or production network is attacked.

**Mitigation**  
`cloud-server/outbound-dns-pinning.js` caches only the just-validated public resolution for a short TTL, consumes it once, and injects a connection `lookup` callback so the socket uses that validated address. Private/reserved results are never cached. Installed before `server-core` loads.

**Protecting test**  
`cloud-server/tests/outbound-dns-pinning.test.cjs`; dedicated F0/0.9 CI executes it.

### P1-02 — Windows public artifact can lack OS Authenticode/RFC3161 on canonical integration — FIX CANDIDATE EXISTS, NOT INTEGRATED

**Vector**  
Tauri updater signing authenticates updater artifacts but does not create a Windows Authenticode signature on the executable/installer. Treating those signatures as equivalent could allow a public Windows release to be presented as OS-signed when it is not.

**Impact**  
Weaker publisher identity/integrity assurance for Windows distribution; SmartScreen/trust impact and an unsafe release-governance claim.

**Evidence / affected paths**  
`.github/workflows/build-windows.yml`, `.github/workflows/release-desktop-updater.yml`; updater signing contract in `scripts/regression-phase12b.mjs`. Separate PR #88 adds a fail-closed Authenticode + mandatory RFC3161 seam, but its branch diverges from the canonical integration baseline and therefore must not be blindly retargeted.

**Reproducibility**  
Static workflow inspection: updater key is present, while canonical integration has no equivalent verified `signtool verify /pa` + timestamp gate for public Windows artifacts.

**Mitigation**  
Port/rebase the PR #88 seam cleanly onto the canonical integration branch, keep signer/certificate outside repo, require SHA-256 + RFC3161, and block `public/stable` publication unless Authenticode verification and timestamp verification succeed. Internal builds may remain unsigned but must never be labeled public-signed.

**Protecting test**  
The Authenticode guard/seam tests introduced by PR #88 plus Windows-native release CI. Public release remains NO-GO until integrated and verified.

### P2-01 — Production web edge omits CSP/HSTS

**Vector**  
`deploy/web/beatgaler.com.conf` supplies TLS and several headers but does not emit a Content-Security-Policy or Strict-Transport-Security header for the browser document.

**Impact**  
Reduces defense-in-depth against future XSS/content injection and HTTPS downgrade/first-visit weaknesses. No direct XSS primitive was established in this audit.

**Evidence / affected path**  
`deploy/web/beatgaler.com.conf`; contrast with restrictive Tauri CSP in `src-tauri/tauri.conf.json` and API security headers.

**Reproducibility**  
Static configuration inspection.

**Mitigation**  
Add a web-specific CSP compatible with built assets and HSTS after confirming domain/subdomain deployment policy; include `frame-ancestors`, `object-src`, `base-uri`, `form-action` and constrained connect/img sources.

**Protecting test**  
Extend productive-web hardening regression to parse nginx headers and fail if required CSP/HSTS directives disappear.

### P2-02 — Auth rate limiting is process-local

**Vector**  
`cloud-server/auth-abuse-controls.js` keeps counters/backoff in process memory. Multiple replicas/process restarts multiply or reset the effective allowance.

**Impact**  
Brute-force/account-recovery/OAuth abuse controls are weaker in horizontally scaled production than the per-process tests imply.

**Evidence / affected path**  
`cloud-server/auth-abuse-controls.js` in-memory maps; production architecture supports shared PostgreSQL for other authorization state.

**Reproducibility**  
Run two isolated limiter instances: each grants its own quota for the same IP/account tuple.

**Mitigation**  
Move security-sensitive counters to shared PostgreSQL/Redis or enforce equivalent shared ingress/WAF limits. Preserve account + IP dimensions and bounded retention.

**Protecting test**  
Cross-process integration test proving aggregate quota is not multiplied by replica count.

### P2-03 — Reproducible SBOM artifact not evidenced in audited release tree

**Vector**  
Release/package workflows can ship without a machine-readable dependency inventory tied to the artifact.

**Impact**  
Slower incident response and incomplete supply-chain traceability during dependency advisories.

**Evidence / affected paths**  
No `SBOM`, CycloneDX, SPDX, `syft`, or equivalent generator/artifact was found in the audited repository/workflow search. The plan may describe SBOM as a closed governance item, but code/runtime evidence must prevail.

**Reproducibility**  
Repository/workflow search over the canonical baseline.

**Mitigation**  
Generate CycloneDX/SPDX from locked JS + Rust graphs in release CI, bind it to source/artifact SHA and publish alongside artifacts.

**Protecting test**  
Release regression fails if the expected SBOM file is absent or does not include source/artifact identity.

### P2-04 — Provenance is checksum metadata, not signed attestation

**Vector**  
`write-runtime-provenance.mjs` creates JSON containing git SHA, sources, sizes and SHA-256 digests, but the record itself is not cryptographically attested.

**Impact**  
Useful traceability but weaker tamper-evidence/identity than signed provenance (for example SLSA-style attestations).

**Evidence / affected path**  
`scripts/write-runtime-provenance.mjs`.

**Reproducibility**  
Static script inspection.

**Mitigation**  
Bind provenance to immutable release artifacts and sign/attest it with a workload identity or approved signing service. Keep existing checksum metadata as input.

**Protecting test**  
Release workflow must fail if signed attestation is absent or subject digest differs from shipped artifact.

### P3-01 — Tauri asset protocol scope is broader than necessary

**Vector**  
`src-tauri/tauri.conf.json` uses broad asset protocol scope while filesystem plugin permissions themselves are application-recursive.

**Impact**  
Increases local-file exposure blast radius if a renderer-origin compromise/XSS is introduced later.

**Evidence / affected path**  
`src-tauri/tauri.conf.json`, `src-tauri/capabilities/default.json`.

**Reproducibility**  
Static config inspection.

**Mitigation**  
Constrain asset protocol scope to required application/cache/media paths and keep renderer CSP restrictive.

**Protecting test**  
Tauri hardening regression asserts an explicit allowlist instead of `**`.

### P3-02 — Log redaction primarily relies on sensitive field names

**Vector**  
`operations-observability.js` recursively redacts keys matching token/secret/password/authorization/cookie, but arbitrary fields containing credential-like values may not match by key.

**Impact**  
Accidental secret/PII leakage if future callers pass raw payloads under neutral key names.

**Evidence / affected path**  
`cloud-server/operations-observability.js`.

**Reproducibility**  
Pass `{ value: "Bearer ..." }`; key-name matcher alone does not identify the semantic secret.

**Mitigation**  
Prefer explicit structured allowlists for security logs; add value-pattern redaction for common bearer/cookie/key formats; never log raw request bodies.

**Protecting test**  
Redaction fixtures with secrets under neutral field names.

### P3-03 — Local MASTER session plaintext fallback

**Vector**  
`cloud-server/master-storage.js` may read `cloud-server/master-session.txt` if the environment value is absent.

**Impact**  
Credential theft from a compromised local filesystem/backup if permissions are weak. The file is Git-ignored; no repository disclosure was found.

**Evidence / affected paths**  
`cloud-server/master-storage.js`, `.gitignore`.

**Reproducibility**  
Static fallback inspection.

**Mitigation**  
Disallow file fallback in production or enforce restrictive permissions and migrate the credential to the production secret provider.

**Protecting test**  
Production startup contract rejects file-backed MASTER credentials.

## 5. Important non-findings / withdrawn hypotheses

- **Cross-user installation rebind**: an isolated read of `bindInstallationToBeatGalerUser()` suggested account B could overwrite an installation claim. Full middleware composition showed `http-containment.js` intercepts the relevant auth/OAuth routes first, rejects another owner's installation ID and requires PostgreSQL cross-process coordination in production. The hypothesis is withdrawn and is not counted as a finding.
- **Trash physical-delete failure**: `purgeWebTrash()` commits the tombstone/index state before best-effort media deletion. Failure can leave orphaned storage but does not restore user-visible access; this is the safer failure ordering.
- **Updater signing**: Tauri updater signatures are present and verified; P1-02 exists only because this is not the same control as Windows Authenticode.
