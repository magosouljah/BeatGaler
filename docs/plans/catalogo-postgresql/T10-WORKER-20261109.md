## 2. Reglas fijadas (C8)

- **Claim:** `FOR UPDATE SKIP LOCKED`, ≤10 por iteración, solo `QUEUED` con `next_attempt_at <= now()`; `lease_generation + 1` en cada adquisición; `lease_until = now() + 60 s`. El lease vencido lo reclama otro worker con generación +1; `completeJob/failJob/renewJobLease` con token viejo → `LEASE_FENCED` (nada se confirma).
- **Efecto remoto sin SQL retenida (C1.5):** el handler lee el estado en una transacción corta, libera el cliente y después llama al transporte; el resultado se persiste en otra transacción con fencing (`recordVerification` comprueba generación y época). La renovación del lease corre en su propio cliente breve cada `renewEveryMs`.
- **Fallos:** transitorio → `QUEUED` con backoff exponencial (tope 15 min) o `Retry-After` de FLOOD_WAIT; permanente → `BLOCKED` inmediato; 8 transitorios → `BLOCKED`. `BLOCKED` queda visible en `health()` y nunca se reintenta solo.
- **Envío incierto:** `cancel` tras despacho → `RECONCILE`; el worker **busca** por identidad persistida (`sender_id`, `random_id`) y nunca reenvía. 0 coincidencias = incierto (sigue en RECONCILE, retry acotado); 1 = adopta; >1 = BLOCKED.
- **Checkpoints:** query sets avanzan por frontera y no recalculan miembros ya publicados; bulk avanza por lotes de 50 con `expected_revision`; una escritura externa (revisión o versión de miembro) produce `CONFLICT` y el job termina `DONE`. Reanudar exige `resumeOperation` con la revisión actual explícita (no hay retry ciego); un miembro con versión distinta vuelve a conflicto hasta cancelar o reseleccionar (T07).
- **Health:** `backlog`, `leased`, `blocked`, `oldestAgeMs`, `expiredLeases`, `running`, métricas; Cloud no depende del worker para servir lecturas ni mutaciones.

## 3. Decisiones

- **D-T10-1:** ids de continuación acotados: `<root>-c<n>` con `root` = job original; nunca crecen por anidamiento (límite 64 chars de `job_id`).
- **D-T10-2:** el recibo del cliente encola la verificación en vez de confiar en el cliente; el commit 202 encola su propio reintento. Un cliente sin worker activo queda en `PENDING_VERIFICATION`/202 sin pérdida.
- **D-T10-3:** PURGE se encola pero queda `BLOCKED NOT_IMPLEMENTED` hasta T15 (visible, sin efecto).
- **D-T10-4:** el worker real exige el gateway de T11 (§8.6); el fake solo modela `verify`/`search`/FLOOD_WAIT. G2 sigue requiriendo sandbox autorizado.
